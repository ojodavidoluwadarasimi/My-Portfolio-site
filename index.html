Project 01

ScoreWise CBT Portal

A computer based testing platform designed to help students prepare for JAMB UTME and Post UTME examinations.

  • PurposeRealistic computer based practice for exam candidates.
  • FeaturesInteractive examinations, subject categories, student authentication, performance tracking, examination review and an expanding question bank.

“I enjoy building technology that makes learning more accessible, engaging and effective.”

HTML5CSS3JavaScriptPythonFastAPISupabasePostgreSQLVercel
Live Preview Source Code

Overview

A computer based testing platform designed to help students prepare for JAMB UTME and Post-UTME examinations through realistic practice.

Problem being addressed

Many students lack access to authentic computer based exam practice that mirrors the real JAMB interface and experience.

Solution

ScoreWise provides a realistic CBT environment with timed exams, subject categories, authentication, performance tracking, examination review and an expanding question bank.

Key implemented features

  • Interactive examinations with a realistic CBT interface
  • Subject categories and levels
  • Student authentication
  • Performance tracking and review
  • Expanding question bank
  • Keyboard shortcuts
  • Dark mode
  • Short lessons and study helpers

Technology stack

HTML5, CSS3, JavaScript, Python, FastAPI, Supabase, PostgreSQL, Vercel.

System architecture

Frontend · HTML / CSS / JS→FastAPI backend→Supabase · PostgreSQL + Auth·Vercel

Important engineering decisions

  • Realistic exam UI that closely mirrors the official CBT experience
  • Supabase for rapid authentication and database needs
  • Progressive feature addition while keeping the core exam flow solid

Challenges encountered

  • Creating a faithful CBT interface that remains usable
  • Managing question data and performance tracking cleanly
  • Balancing feature richness with simplicity for students

Lessons learned

  • Real user context drives better design decisions
  • A working vertical slice is more valuable early than many incomplete features
  • Clear separation between exam interface and supporting tools improves maintainability

Potential improvements

  • Richer analytics
  • More advanced question generation
  • Better admin tooling
  • Performance and accessibility refinements

Project 02

Kicks & Cuffs

An e-commerce platform focused on footwear, built as a real online store for small sellers.

  • PurposeTurn a small seller's business idea into a working shop.
  • FeaturesProduct discovery, size based inventory, cart, checkout, online payments with Paystack, order tracking and an owner dashboard.

“I enjoy transforming business ideas into functional digital experiences that solve practical problems.”

HTML5CSS3JavaScriptPostgreSQLSupabasePPaystackVercel
Live Preview Source Code

Overview

An e-commerce platform focused on footwear, built as a real online store for small sellers.

Problem being addressed

Small footwear sellers often lack a clean, functional online store that handles size based inventory, payments and order tracking without excessive complexity.

Solution

Kicks & Cuffs is a working e-commerce experience that supports product discovery, size based inventory, cart, checkout, online payments through Paystack, order tracking and an owner dashboard.

Key implemented features

  • Product discovery and browsing
  • Size based inventory management
  • Shopping cart
  • Checkout flow
  • Online payments with Paystack
  • Order tracking
  • Owner dashboard

Technology stack

HTML5, CSS3, JavaScript, PostgreSQL, Supabase, Paystack, Vercel.

System architecture

Storefront · HTML / CSS / JS→Supabase · PostgreSQL + Auth·Paystack payments·Vercel

Important engineering decisions

  • Size as a first class inventory dimension
  • Real Paystack payments, with payment handling kept off the client through a Supabase Edge Function
  • Simple owner dashboard for operational control
  • Clean, product focused UI

Challenges encountered

  • Correct size based stock handling
  • Reliable payment and order state management
  • Building something that feels like a real store rather than a demo

Lessons learned

  • Real payment and inventory constraints force better system design
  • Small sellers need clarity and reliability more than feature volume
  • Practical end to end flows matter more than theoretical architecture early on

Potential improvements

  • Better inventory alerts and analytics
  • Improved order management tooling
  • Performance and mobile refinements
  • Additional payment or delivery options
